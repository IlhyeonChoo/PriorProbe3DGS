## 1. 경위

Phase 5 실험에서 prior Gaussian의 **좌표계 불일치 버그**가 발견되었다.

- 정렬 기준: canonical seed frame
- 실제 삽입: scene/world frame의 원본 splat.ply

이로 인해 prior가 target object로부터 **1.1~6.0m 떨어진 위치**에 삽입되고 있었다.
버그를 수정한 후 Phase 5 전 실험(Phase 5.1 원본 5개 + Phase 5.2 sweep 4개)을 재실행했다.

## 4. 분석

### 4.1 "올바른 삽입이 왜 나쁜가" — 간섭 가설

올바른 스케일의 prior는 target object 영역을 정확히 점유한다.

1. SfM gaussian과 직접 공간 겹침 발생
2. 보호 설정(lr_scale=0.05, prune/densify 보호 ON)에 의해 prior가 반고정 상태로 유지
3. "거의 맞지만 완벽하지 않은" prior가 최적화의 local minimum을 형성
4. prior 수가 많을수록 점유 영역이 넓어져 간섭 증가

이를 뒷받침하는 증거:
- **Prior 수 ↔ 악화**: full(-0.229/-1.630) > 100K(-0.339/-0.716) > 75K(-0.068/+0.241) > 50K/25K(~0)
- **full_none(보호 해제)이 office_0에서 유일한 양수**: 보호 해제 시 prior가 자유롭게 수정되어 간섭 해소

### 4.2 "잘못된 삽입이 왜 좋았는가" — 미해결 문제

간섭 가설은 "올바른 삽입이 왜 나쁜가"만 설명한다.
**"잘못된 위치의 prior가 왜 이득을 줬는가"는 설명되지 않는다.**

잘못된 위치(1~6m 오차)라면:
- 무시되어야 하거나 (중립)
- 방해가 되어야 한다 (음수)
- 이득이 있으면 안 된다

### 4.3 Baseline 변동 문제 — confounding

Prior가 없는 **baseline 결과 자체가 legacy와 new에서 다르다.**

| Scene | legacy baseline | new baseline | Δ | Gaussian 수 변화 |
|-------|----------------:|-----------:|---:|--------:|
| room_0 | 46.682 | 46.606 | -0.076 | 207,338 → 219,137 (+5.7%) |
| office_0 | 43.737 | 44.201 | **+0.464** | 225,564 → 239,572 (+6.2%) |

Baseline은 prior를 삽입하지 않으므로 alignment 수정의 직접 영향을 받지 않는다.
그런데도 **office_0 baseline이 +0.464 dB, gaussian 수 +14K**나 차이난다.

이는 alignment 수정 외에 다른 코드 변경이 있었거나, 학습의 비결정적 요소가 영향을 줬음을 시사한다.

### 4.4 가능한 해석 두 가지

#### 해석 A: Legacy의 prior 이득이 허상이었다

코드 변경이 alignment 외의 부분도 영향을 줬다면:

- Legacy 시점의 코드에서 baseline의 densification이 약했고 (207K/225K)
- Prior 실험은 추가 gaussian 수(125K~251K 초기 시작)로 이 한계를 보완
- 즉, **prior의 위치/형태가 아니라 추가 primitive 수 자체가 효과를 낸 것**

이 가설이 맞다면:
- Legacy 100K가 best였던 이유 = "200K로 시작해서 가장 많았기 때문"
- Prior의 위치나 형태는 무관, 더 많은 gaussian이 유리했을 뿐

#### 해석 B: Densification 동작 변경

New 코드가 더 적극적으로 densify (207K→219K, 225K→239K):

- New baseline이 이미 충분히 dense → prior 추가의 한계효용 감소
- Legacy baseline은 덜 dense → prior가 커버리지 공백을 메움

어느 해석이든 **prior의 "올바른 위치"는 핵심이 아니며, primitive 수 보충 효과**가 본질.
